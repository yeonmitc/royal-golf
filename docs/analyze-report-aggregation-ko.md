# `/analyze`와 `/report` 집계 기준 (2026-11-10)

## 공통 판매 기준

- 기간은 판매일 `sold_at`으로 조회한다. 환불행, 수량 0 이하, Ella 판매, `SU-OT`로 시작하는 코드, 코드 조각이 정확히 `EA`인 상품은 판매 집계에서 제외한다.
- `gift`는 `free_gift = true` 또는 판매 단가 0으로 판별한다. 매출은 0이며 커미션도 0이다. 손실은 **판매가가 아니라 상품 원가 × 수량**이다.
- 상품 원가는 `products.p1price`가 양수이면 그 값(PHP), 아니면 `products.kprice / 25`(PHP)를 사용한다. 두 값이 모두 없으면 0으로 집계된다.
- 총매출은 비 gift 판매의 실제 단가 `sales.price × qty` 합계다. Mr. Moon, Peter, Kakao 할인은 이미 실제 단가에 반영되어 다시 차감하지 않는다.
- Nowtravel 15% 할인도 동일하게 실제 `sales.price`를 사용한다. 판매 화면은 정상가 1,000 PHP 초과 상품에 해당 할인율을 적용하고 100 PHP 단위로 올림한 금액을 `sales.price`에 저장한다. 실제 결제액을 나중에 정상가나 할인율로 다시 추정하지 않는다.
- 시트에만 적힌 영수증 단위 현금 조정액이 판매행의 `sales.price`에 반영되지 않았다면 현재 두 화면은 그 차액을 알 수 없다. 해당 거래의 실제 수령액을 맞추려면 저장된 판매 단가를 확인해야 한다.
- 가이드 커미션은 정산 지급 시점이 아닌 판매 발생 시점에 비용으로 잡는다. `sale_groups.guide_commission`이 양수이면 이를 해당 그룹의 유상 판매금액 비율로 배분한다. 저장값이 0인 가이드 그룹은 유상 판매금액의 10%를 대체값으로 사용한다. Mr. Moon, Peter, Ella, gift에는 커미션을 배분하지 않는다.

## 화면별 계산식

| 의미 | `/analyze` | `/report` |
|---|---|---|
| 총매출 | `Total Sales` | `총매출` |
| 상품 및 gift 원가 | `Cost` 한 카드에 합산 | `상품원가`와 `선물원가`로 분리 |
| 가이드 커미션 | `회사 가이드 커미션 합계`와 `로컬 가이드 커미션 합계`로 분리; `Total Sales - Guide Comm`에는 두 합계 반영 | `가이드 커미션` |
| 원가 차감 후 | `Gross Profit = 총매출 - 상품원가 - 선물원가` | `매출이익 = 총매출 - 상품원가 - 선물원가` |
| 지출 | `Total Expense`: 기간 내 모든 `expenses` | 운영비 합계(직원 월급, 운영비, 물류비, 부자재, 기타)와 의류 사입비로 분리 |
| 모든 비용 차감 후 | `Net Profit = 총매출 - 원가 - 가이드 커미션 - 전체 지출` | `최종순수익 = 매출이익 - 가이드 커미션 - 운영비 합계 - 의류 사입비` |

`/report`의 `순수익`은 의류 사입비를 차감하기 전 단계다. 따라서 같은 기간을 비교할 때 `/analyze`의 `Net Profit`은 `/report`의 **최종순수익**과 비교한다. `/report`의 월별 합계와 `/analyze`의 날짜 범위가 정확히 같아야 한다.

동일 기간의 서버 데이터가 같을 때 비교 대상은 `Total Sales` ↔ `총매출`, `Cost` ↔ `상품원가 + 선물원가`, `Gross Profit` ↔ `매출이익`, `Net Profit` ↔ `최종순수익`이다. `/report`의 `순수익`은 의류 사입비 차감 전이므로 `/analyze` `Net Profit`과 다른 숫자가 정상일 수 있다. 판매가 없는 기간에도 `/analyze`는 지출을 계산하며, `/report`는 지출을 페이지 단위로 끝까지 조회한다.

`expenses.amount_krw`는 각 지출행마다 양수 금액을 `ceil(KRW / 25)` PHP로 환산하고 `amount_php`를 더한다. 현금 할인가 카드, 실제 가이드 정산 지급액, 미정산 잔액은 위 손익에서 추가 차감하지 않는다.

`/analyze`의 회사·로컬 가이드 카드는 해당 기간에 **발생한 커미션**을 `guides.guide_type`의 `regular`와 `local`로 나눈 금액이다. 기존 AOV와 Total Commission 카드는 표시하지 않는다. Mr. Moon, Peter, Kakao, Nowtravel의 **현금 할인가** 카드는 할인 차액이 아닌 각 채널에서 실제 받은 `sales.price × qty` 합계다. `Refund Amount`는 선택 기간에 **판매된 행 중 나중에 환불된 행**의 실제 판매금액 합계다. 환불일이 선택 기간에 들어왔다는 뜻은 아니다. Ella, `SU-OT`, 코드 조각 `EA`는 환불액에서도 제외한다.

## 코드 경로와 확인 사항

- `/analyze`: `AnalyzePage.jsx` → `salesApiClient.getAnalytics()` → `salesApiSupabase.getAnalytics()`.
- `/report`: `ReportPage.jsx` → `salesApiClient.getSalesSummaryRows()` → `salesApiSupabase.getSalesSummaryRows()`.
- 두 화면 모두 서버 조회 실패가 네트워크 오류이면 `salesApi.js`의 로컬 폴백을 사용한다. 로컬 데이터 상태가 서로 다르면 서버 기준 비교와 구분해야 한다.
- 운영 DB의 2026년 10월 판매 284행과 연결된 판매그룹 184개를 읽기 전용으로 확인했다. 화면의 총매출 364,100 PHP는 DB의 실제 `price × qty` 합계와 일치했다.
- 원가 차이 **2,912 PHP**는 환불된 5행의 원가 합계와 정확히 일치했다. 기존 `/report`가 이 환불행 원가를 포함해 123,202 PHP로 계산했고, `/analyze`의 유효 판매 원가는 120,290 PHP였다. 환불행을 `/report` 집계에서 제외했다.
- Kakao 판매는 67행(유상 66행, gift 1행)이고, 62행에 정상가와 실제 결제 단가 차이가 있다. 정상가 합계 162,300 PHP, 실제 수령액 **148,900 PHP**다. 기존 `/analyze`는 `sale_groups.local_guide_name`을 읽지 않아 Kakao 카드가 0이었다. 이 조회를 수정했다. 새 현금 할인가 카드는 148,900 PHP를 표시한다.
- Peter 판매 11행의 실제 수령액은 **26,600 PHP**이고 저장된 `list_price` 합계도 26,600 PHP다. 모든 행에서 두 단가가 같아 저장 데이터만으로 할인 차액을 계산할 수 없지만, 새 현금 할인가 카드는 실제 수령액 26,600 PHP를 표시한다. 가이드 연결 누락은 아니다.
- Mr. Moon의 실제 수령액은 **61,900 PHP**다. 10월 조회 결과에는 커미션 대상 일반·로컬 가이드 판매가 없어 두 가이드 커미션 카드가 모두 0이다. Nowtravel 현금 할인가 카드는 기존에 존재하지 않았으며 추가했다.
- 제공된 11월 8일 판매 시트는 10월 1~31일 선택 화면과 기간이 다르다. 추가 제공된 10월 시트는 기간이 맞지만, 시트의 정상가가 DB `list_price`에 보존되지 않은 판매는 정확한 과거 할인액을 산출할 수 없다.
